# 研修医 症例・手技ログ（試作版）

初期研修医のための症例・手技記録アプリ。**端末内のみ保存・患者ID匿名化**の方針で作った試作版です。

## 特徴
- 📷 写メから患者IDをOCRで読み取り（**画像は保存しません**）
- 🔒 患者IDは **SHA-256でハッシュ化 → 匿名コード（P001…）** に変換して保存（生IDは一切残らない）
- 🏷 疾患名・手技・施行日・監督者・メモを記録
- 🩺 手技プリセット（腰椎穿刺・気管挿管・CVC など）＋自由入力
- 📋 一覧・検索／📊 手技ごと・監督者ごとの件数集計
- ⬇️ CSV書き出し／取込（将来のGoogleドライブ連携の布石）
- 📱 PWA：iPhone/Android のホーム画面に追加してアプリのように使える
- 🌐 オフライン動作（初回読み込み後）※OCRの初回だけ通信が要ります

## ファイル構成
| ファイル | 役割 |
|---|---|
| `index.html` | 画面 |
| `app.js` | ロジック（保存・匿名化・OCR・集計） |
| `manifest.json` / `sw.js` / `icon.svg` | PWA（ホーム画面追加・オフライン） |

## 動かし方（PCで確認）
```bash
cd kenshu-app
python3 -m http.server 8766
# ブラウザで http://localhost:8766 を開く
```

## スマホで使う
同じWi-Fi内のPCでサーバーを立て、スマホのブラウザで `http://<PCのIP>:8766` を開く。
- 📷 写メ取り込み（写真の選択/撮影）は http でも動きます
- ホーム画面追加・オフラインは **https が必要**（後述の公開方法で対応）

### 本番でスマホに公開（https化）＆ QR配布
データは各自のスマホ内に保存されるので、アプリ本体を公開してもサーバーに患者情報は送られません。

#### A. Netlify Drop（最も簡単・git不要）
1. プロジェクト直下の `kenshu-app-deploy.zip` を解凍（フォルダを用意）
2. [app.netlify.com/drop](https://app.netlify.com/drop) を開く
3. そのフォルダを画面にドラッグ＆ドロップ
4. 数秒で `https://〇〇.netlify.app` のURLが発行される（無料）
5. アプリの「☁️ 同期」タブ →「QRコードを表示」で、そのURLのQRが出る
6. 同僚がカメラでQRをスキャン → 開く →「ホーム画面に追加」

> URLを固定・管理したい場合はNetlifyに無料登録しておくと、サイト名やドメインを管理できます。

#### B. GitHub Pages（無料・恒久／GitHubアカウント要）
1. リポジトリを作成し、`kenshu-app/` の中身をプッシュ
2. Settings → Pages → Branch を `main` / root に設定
3. `https://<ユーザー名>.github.io/<リポジトリ>/` で公開

#### ⚠️ 公開後にやること（Drive連携を使う場合）
Google Cloud Console の OAuthクライアントID設定で、**承認済みのJavaScript生成元**に
公開URL（例：`https://〇〇.netlify.app`）を**追加**してください。これを忘れるとDrive連携が認証エラーになります。

## ⚠️ 重要な注意
- 本アプリは**匿名化済みデータのみ**を端末内に保存します。生の患者IDや写真は保存しません。
- それでも、実運用の前に**所属病院の個人情報窓口・規定**に「研修記録（症例ログ）アプリの利用可否」を必ず確認してください。
- メモ欄に患者の氏名など個人を特定できる情報は書かないでください。

## ☁️ Googleドライブ連携（同期タブ）
匿名化済みデータ（症例・手技・コード対応表）だけを、自分のDrive上の `kenshu_backup.json` にバックアップ/復元できます。**生のID・写真は同期されません。**

### 初回セットアップ（1回だけ）
1. [Google Cloud Console](https://console.cloud.google.com/) でプロジェクト作成
2. 「APIとサービス」→「ライブラリ」で **Google Drive API** を有効化
3. 「OAuth同意画面」を構成（User type=外部、テストユーザーに自分のGmailを追加）
4. 「認証情報」→「OAuthクライアントID」→ 種類=**ウェブアプリケーション**
5. **承認済みのJavaScript生成元** にアプリのURLを追加
   - ローカル確認：`http://localhost:8766`
   - 公開後：`https://<あなたのドメイン>`
6. 発行された **クライアントID** をアプリの「同期」タブに貼り付けて保存

### 使い方
- **☁️ Driveへバックアップ**：現在の全データをDriveへ保存（上書き）
- **⬇️ Driveから復元**：Driveの内容でこの端末を上書き（新しいスマホへの移行に）

### 仕組み・権限
- スコープは `drive.file`（**このアプリが作ったファイルだけ**にアクセス／Drive全体は読めません）
- クライアントIDは「公開情報」で秘密鍵ではありません（端末内に保存）
- 1端末＝1バックアップを基本とした想定（複数端末で同時編集する運用は将来対応）
