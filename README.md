# 研修医 症例・手技ログ（試作版）

初期研修医のための症例・手技記録アプリ。**端末内のみ保存・患者ID匿名化**の方針で作った試作版です。

## 特徴
- 📷 写メから患者IDをOCRで読み取り（**画像は保存しません**）
- 🔒 患者IDは **SHA-256でハッシュ化 → 匿名コード（P001…）** に変換して保存（生IDは一切残らない）
- 🏷 疾患名・手技・施行日・監督者・メモを記録
- 🩺 手技プリセット（腰椎穿刺・気管挿管・CVC など）＋自由入力
- 📋 一覧・検索／📊 手技ごと・監督者ごとの件数集計
- ⬇️ CSV書き出し／取込（将来のGoogleドライブ連携の布石）
- 📱 PWA：iPhone/Android のホーム画面に追加してアプリのように使える
- 🌐 オフライン動作（初回読み込み後）※OCRの初回だけ通信が要ります

## ファイル構成
| ファイル | 役割 |
|---|---|
| `index.html` | 画面 |
| `app.js` | ロジック（保存・匿名化・OCR・集計） |
| `manifest.json` / `sw.js` / `icon.svg` | PWA（ホーム画面追加・オフライン） |

## 動かし方（PCで確認）
```bash
cd kenshu-app
python3 -m http.server 8766
# ブラウザで http://localhost:8766 を開く
```

## スマホで使う
同じWi-Fi内のPCでサーバーを立て、スマホのブラウザで `http://<PCのIP>:8766` を開く。
- 📷 写メ取り込み（写真の選択/撮影）は http でも動きます
- ホーム画面追加・オフラインは **https が必要**（後述の公開方法で対応）

### 本番でスマホに公開（https化）＆ QR配布
データは各自のスマホ内に保存されるので、アプリ本体を公開してもサーバーに患者情報は送られません。

#### A. Netlify Drop（最も簡単・git不要）
1. プロジェクト直下の `kenshu-app-deploy.zip` を解凍（フォルダを用意）
2. [app.netlify.com/drop](https://app.netlify.com/drop) を開く
3. そのフォルダを画面にドラッグ＆ドロップ
4. 数秒で `https://〇〇.netlify.app` のURLが発行される（無料）
5. アプリの「☁️ 同期」タブ →「QRコードを表示」で、そのURLのQRが出る
6. 同僚がカメラでQRをスキャン → 開く →「ホーム画面に追加」

> URLを固定・管理したい場合はNetlifyに無料登録しておくと、サイト名やドメインを管理できます。

#### B. GitHub Pages（無料・恒久／GitHubアカウント要）
1. リポジトリを作成し、`kenshu-app/` の中身をプッシュ
2. Settings → Pages → Branch を `main` / root に設定
3. `https://<ユーザー名>.github.io/<リポジトリ>/` で公開

#### ⚠️ 公開後にやること（Drive連携を使う場合）
Google Cloud Console の OAuthクライアントID設定で、**承認済みのJavaScript生成元**に
公開URL（例：`https://〇〇.netlify.app`）を**追加**してください。これを忘れるとDrive連携が認証エラーになります。

## ⚠️ 重要な注意
- 本アプリは**匿名化済みデータのみ**を端末内に保存します。生の患者IDや写真は保存しません。
- それでも、実運用の前に**所属病院の個人情報窓口・規定**に「研修記録（症例ログ）アプリの利用可否」を必ず確認してください。
- メモ欄に患者の氏名など個人を特定できる情報は書かないでください。

## ☁️ Googleドライブ連携（同期タブ）
匿名化済みデータ（症例・手技・コード対応表）だけを、自分のDrive上の `kenshu_backup.json` にバックアップ/復元できます。**生のID・写真は同期されません。**

### 初回セットアップ（1回だけ）
1. [Google Cloud Console](https://console.cloud.google.com/) でプロジェクト作成
2. 「APIとサービス」→「ライブラリ」で **Google Drive API** を有効化
3. 「OAuth同意画面」を構成（User type=外部、テストユーザーに自分のGmailを追加）
4. 「認証情報」→「OAuthクライアントID」→ 種類=**ウェブアプリケーション**
5. **承認済みのJavaScript生成元** にアプリのURLを追加
   - ローカル確認：`http://localhost:8766`
   - 公開後：`https://<あなたのドメイン>`
6. 発行された **クライアントID** をアプリの「同期」タブに貼り付けて保存

### 使い方
- **☁️ Driveへバックアップ**：現在の全データをDriveへ保存（上書き）
- **⬇️ Driveから復元**：Driveの内容でこの端末を上書き（新しいスマホへの移行に）

### 仕組み・権限
- スコープは `drive.file`（**このアプリが作ったファイルだけ**にアクセス／Drive全体は読めません）
- クライアントIDは「公開情報」で秘密鍵ではありません（端末内に保存）
- 1端末＝1バックアップを基本とした想定（複数端末で同時編集する運用は将来対応）

## 📊 GASで集計（同期タブ「集計シートへ送信」）
アプリから匿名化データを Google Apps Script（GAS）の Web App に送り、**Googleスプレッドシートで自動集計**します。Cloud ConsoleのOAuth設定は不要です。

### セットアップ（1回だけ）
1. Googleスプレッドシートを新規作成
2. **拡張機能 → Apps Script** を開く
3. `gas/Code.gs` の中身を全部貼り付けて保存
4. コード冒頭の `SHARED_KEY` を好きな合言葉に変更（例：`kensyu2026`）
5. **デプロイ → 新しいデプロイ → 種類「ウェブアプリ」**
   - 実行するユーザー：**自分**
   - アクセスできるユーザー：**全員**
6. 発行された **ウェブアプリURL（末尾 `/exec`）** をコピー

### アプリ側の設定
1. 「☁️ 同期」タブ →「📊 集計シートへ送信（GAS）」
2. **GAS Web App URL** に上記URLを貼る
3. **合言葉** をGASの `SHARED_KEY` と同じにする
4. （任意）**研修医名/ID** を入れると、複数人のデータをシートで区別できる
5. 「設定を保存」→「📤 シートへ送信」

### できること
- スプレッドシートに「症例」「手技」シートが自動生成され、データが追記される（id重複は自動で更新）
- 「集計」シートに **手技別・疾患別・研修医別の件数** が自動作成される
- 複数の研修医が同じURL・合言葉で送れば、**1枚のシートに集約**（指導医・研修委員会の集計に便利）
- さらにスプレッドシートのピボットテーブル/グラフで自由に分析可能

### 注意
- 送信されるのは**匿名化データのみ**（P001等／生ID・写真なし）
- 応答はブラウザのCORS制約で読めないため、送信後は**スプレッドシートで結果を確認**してください
- 合言葉は簡易的な保護です。URLは関係者だけに共有してください

## 🗺 登録クリニック マップ（`map/`）

登録医一覧（2026/05更新）の **185施設** を地図上に表示し、診療科目で色分けしたページです。

```
map/index.html      画面（Leaflet）
map/clinics.js      施設データ185件（PDFから抽出・自動分類）
map/clinics_geo.json 位置データ（初期は空。書き出したものを置き換えると全員が同じ位置で見られる）
map/vendor/leaflet/ Leaflet 1.9.4 一式（CDN不要）
```

### 色分け
| 色 | 分類 | 件数 | 判定に使う語 |
|---|---|---|---|
| 🔵 青 | 内科系（内科・小児科） | 101 | 診療科目に「内科」または「小児科」 |
| 🟢 緑 | 歯科系 | 25 | 「歯科」または「口腔外科」 |
| 🔴 ピンク | 婦人科系（産科・婦人科） | 15 | 「産婦人科」「産科」「婦人科」 |
| ⚪️ グレー | その他の科 | 49 | 上のいずれにも当たらない（眼科・耳鼻科・整形外科など） |

複数に当てはまる施設（例：小児科・産婦人科）は **マーカーを色で分割** して表示し、どちらのしぼり込みでも出てきます。

### 使い方
```bash
cd kenshu-app
python3 -m http.server 8766
# ブラウザで http://localhost:8766/map/ を開く
```
GitHub Pages に公開している場合は `https://<ユーザー名>.github.io/<リポジトリ>/map/`。

- 左のチェックで **系統ごとの表示/非表示**、検索窓で医院名・住所・診療科目を検索
- エリア（南部／中部／北部／離島）でしぼり込み
- マーカーまたは一覧をタップで、住所・診療科目・電話（タップで発信）を表示

### 位置（緯度経度）について
住所から座標への変換は、**国土地理院の住所検索API**（`msearch.gsi.go.jp`）をブラウザから呼んで行い、結果は端末内（localStorage）に保存します。2回目以降は通信なしで即表示されます。

- 番地まで一致しなかった住所は、丁目・字レベルまで戻して検索します
- それでも取れないものは**市町村の代表点に仮置き**し、一覧に「概略」、地図にオレンジの点線マーカーで表示します。**ドラッグで正しい位置に直せます**（直した位置も端末内に保存）
- 「データ▾」から **位置データの書き出し（clinics_geo.json）／読み込み／一覧のCSV書き出し／位置の取り直し** ができます
- 書き出した `clinics_geo.json` を `map/` に置いてコミットすると、**全員が同じ位置・通信なし**で開けるようになります

> 地図タイルと住所検索APIは国土地理院のものを使っています（施設データは端末外に送信されません）。

### データを更新するとき
新しい登録医一覧のPDFが出たら、`map/clinics.js` を差し替えます（1件＝1行のJSON形式）。分類（`cats`）は診療科目の文字列から機械的に判定した結果なので、実態と違う場合はその行を直してください。
